## 1. 从标题菜单进入 AI 会话

- 标题页先高亮「开始游戏」；有存档时提供「继续游戏」，开始新局使用现有清档确认。上下键移动，回车和鼠标都可确认。设置可作为菜单项，前提是接入可用设置，例如减少动效。浏览器里的离开操作以返回标题或离开试玩为准。
- 点开始后，左上逐行输出简短启动日志。内容围绕本作实际会用到的概念，例如 `[BOOT] 校验会话模块`、`[SYS] 导入系统提示词`、`[LINK] 接入用户 01 / 02`、`[MEM] 初始化独立记忆区`。续玩时将初始化措辞换成恢复上下文和记忆。日志、字符图案和分隔线都是演出，用它们表现 AI 正在生成自己的操作界面。
- 日志全部输出后停 1.5 秒。接着在实际游戏画面先从上到下画完分隔线，再从左到右逐栏展开男窗、女窗和摘要与记忆。三栏完整可见后再等 1.5 秒，才开始第一条消息或续玩。从确认到可以阅读包含两份临时用户档案及整屏自上而下逐行揭示。档案逐字速度比普通启动日志慢。系统开启减少动态效果时直接显示完成态。菜单阶段和开机阶段不提前触发剧情消息、计时或存档推进。

## 2. 固定画布、双窗和操作光标

- 复用现有 1440×920 固定画布作为实现起点。窗口变化只改变整块画布的显示比例，统一缩放并居中，不横向拉伸、不重新排版；超过设计尺寸时画布不继续放大。游戏开始、长消息、右栏展开、逐字输出或清空都不改变画布外框。两窗和档案各自内部滚动。
- 两个聊天窗等宽并显示 USER 编号与暂用姓名，右边是常驻 CONTEXT STORE，包含 SUMMARY / MEMORY。来信靠左，AI 回复沿用 v0.5.0 的布局：首字靠右，按已显示文字自然展开，达到 400px 上限后换行；`IN` 与 `OUT` 用低饱和色区分，两侧预留标签列。来信右界留在 OUT 列左侧，回复左界比来信缩进约两个字宽；回复的浅灰底仅贴文字，每个换行片段各按自身宽度显示。采用清晰正文、字符线和少量强调色。优先收紧消息间距、窗头和状态占用，再根据浏览器截图调正文大小、栏宽和单屏可读行数。
- 两个聊天窗内，左右键只切换当前操作窗，上下键在该窗当下可选的想法里移动，Enter 发出当前高亮项。鼠标移到可选行时，唯一的 `>` 和整行反白跟到该行；点击直接发出。键盘和鼠标共用一个选择位置。切换操作窗不改哪一窗能播出。无可选项、播放中、弹窗中或聚焦右栏控件时，聊天快捷键不触发发送。右栏先做鼠标展开/折叠，保留普通 Tab 和原生控件的键盘访问，不新增整栏方向键模式。
- 操作光标与会话状态分开。窗头用小字符标记正在播出或待选择的一侧，处理中的状态可用 `/ | \\ -` 转轮。底部给 AI 思考和想法，发送和上下文状态放到窗头或对话流。逐字输出复用已有节拍配置。思考区用 [THINKING]，先显示等待，再快速逐字输出，最后一字完成时立即出现选项；提交时立即收起思考。接收和发送在相应消息原位等待，进入文字后提示消失。

## 3. 存记忆、清空和收录

- 用强调色标出可存原话和按钮，去掉虚线。成功存入时原句轻亮，按钮原位变为 `[MEM] 已存`。保留两窗各自的记忆归属、容量和教学记忆清理。窗头 MEM 点开只显示数量，点外部或再次点击时收起；满槽替换和已存记忆的舍弃在常驻右栏完成。依赖记忆的想法显示 `[MEM]`；没有时按原规则置灰，普通想法始终按原条件可选，持有记忆时仍由玩家决定用不用。
- 章间清空只作用于当前窗。在最后一条消息后追加 `[SYS] 正在清空上下文…`。从最早一条起逐条退场，其余行向上补位，最后系统行改为 `[SYS] 已清空`，短暂停留再退出。视觉过程由现有章间状态驱动，保证原有先后、门槛和章切换生效。
- 清空开始时，右栏同步展开对应人物和本次会话，在具体位置显示「正在收录…」。摘要以每次一到两个字写出，按「人物 → 会话 → 摘要段」折叠，记忆链接挂在来源段下。点击展开角色原话。首个重置默认让玩家看完完整收录再在该窗出现下一条消息；后续在既有调度允许的范围内微调重叠。具体停顿是试玩参数。
- 摘要需单独写成可审的客观短句。用本窗已发生的实际拍和选择匹配摘要及来源，同次收录可含多段；归档展示不参与分支判定。记忆是否可用继续由现有记忆池决定。实现中记录会话与拍的稳定出处，兼容旧档；刷新、重播动画和继续游戏不得重复归档，旧档缺乏历史证据时不编造已发生内容。先做一段并核对内容层规则，再覆盖实际已载入的六幕。
