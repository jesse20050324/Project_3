给后续模型读的交接说明。玩法、设定、现在写进游戏的剧情、代码怎么跑，都以这份为准。台词原文在 `content/`，没写出来的句子见 `content/GAPS.md`。不要把这份概述里的转述写进剧本。

## 这是什么

游戏名叫「双线」（包名 `dual-chat`）。玩家扮演一个 AI 聊天助手，同时看着左右两条对话。左边是「男生」，右边是「女生」。两个人都在跟同一个 AI 说话，互相看不到对方的窗口。玩家两个都看得见。

玩家不能打字。轮到这一侧由玩家决定时，栏底出现几条想法（`thought`）。想法只有玩家看得到。点中之后，聊天记录里出现的是另一句已经写好的回复（`reply`）。这两句是两句不同的话。

画面上有三种字：对面的人发来的消息、AI 已经发出去的消息、只有玩家能看见的内心。内心有两种放法。节拍上的 `aside` 出现在选项上方，不进聊天记录。台词的 `delivery: thought` 作为一条不发出去的记录出现在对话中间。

故事是当代日常生活，地点在西安。说话是口语。AI 发出去的话像一个会办事的助手：短、直接、替人做决定。没有科幻界面，没有立绘。两个人没有名字和脸，界面上就叫「男生」和「女生」。玩家发出的气泡署名是「AI」。

## 现在能玩到哪

可玩内容是「第一幕 · 出发前」和「第二幕 · 桌游店」的男生第一轮。

第一幕：男生三轮。选定店名之后，女生有两轮。女生第一轮没有新的玩家选项，位置和反应跟着店走。女生第二轮三家店相同，她问要不要化妆，可以选「化」或「不化」。

男生说完「OK」，并且女生化妆那句回复也发完之后，才进入第二幕。第二幕按那家店说出不同的到店开场，然后同一套选择：「先刷手机，避免眼神交流」或「主动找人攀谈」。两个做法发出去之后，这一侧停下。第二幕右侧没有节拍。

### 第一幕 · 出发前

文件：`content/chapter-01.yaml`。左侧男生，从出门前选店开始。

1. `L1`。男生说朋友叫他去玩桌游，没定店，要市中心的推荐。玩家只有一个想法：「搜索相关信息，并提供建议」。发出去的是三家店的介绍。然后到 `L2`。
2. `L2`。男生说人有点多，自己在收拾，没时间看，让 AI 直接选一家。三个想法就是三家店。每条回复都是「就选这家」，带上地址、怎么打电话订位、周五晚要早点打。选中的那条写下 `shop`，三条都进入 `L3`。
3. `L3`。男生回「OK」，一下子出现。没有 AI 回复，也没有下一拍。左侧在这里先停，直到第二幕。

右侧女生。她开口要等 `L2` 完成，因为她说的店名就是男生刚选定的那家。不必等男生的「OK」。三家各一拍，没有玩家选项，都进入 `R2`。没选中的两家不会出现。

| 节拍 | 她怎么开口 | AI 先在心里整理，再告诉她位置 | 她的反应 |
| --- | --- | --- | --- |
| `R1-shiguang` | 朋友叫她去「时光桌游吧」，刚起床还没洗脸 | 小寨华旗国际 A 座 | 太贵了，让他换地方 |
| `R1-xindong` | 同上，店名是心动 | 莱安中心 T6-21703 | 感觉还挺好 |
| `R1-xushi` | 同上，店名是叙事者营地 | 大唐不夜城长安 C 位 10 号 | 太远，让他换地方 |

`R2`。她问要不要化妆：时间紧，但好像有不认识的人。玩家选「化」或「不化」。化：简单底妆加口红，半小时内出门。不化：洗把脸直接走。回复说完，右侧停下。这一拍不读 `shop`，三家相同。

### 第二幕 · 桌游店

文件：`content/chapter-02.yaml`。从男生到店开始。`L4-shiguang`、`L4-xindong`、`L4-xushi` 都要等 `L3` 和 `R2`，并且 `shop` 对得上。开场句不同，自言自语和两个做法相同。YAML 用锚点 `&shop-aside`、`&shop-choices` 共用后两段，读入后仍是三拍独立的节拍。

| 节拍 | 开场在说什么 |
| --- | --- |
| `L4-shiguang` | 到了，但换了地方：玩家选的那家他们说太贵了。除了朋友谁都不认识，人多是女生，尴尬 |
| `L4-xindong` | 到了玩家选的那家。除了朋友谁都不认识，人多是女生，尴尬 |
| `L4-xushi` | 到了，但换了地方：玩家选的那家他们说太远了。其余同上 |

两个想法：

- 「先刷手机，避免眼神交流」：先低头装忙，等人齐开桌，别一直刷到不说话。
- 「主动找人攀谈」：问一句平时玩什么桌游，从游戏聊开。

两个做法都没有 `next`。说完左侧停下。女生这一侧第二幕还没有句子。他们最后究竟落在哪一家，草稿没写。

## 代码方案

网页原型。React 19、TypeScript、Vite 6、Tailwind CSS 4。剧本是 YAML，用 `js-yaml` 在启动时解析。测试是 Vitest + Testing Library。没有后端，没有账号。

本地：

```bash
npm install
npm test
npm run dev
```

开发服务器是 <http://127.0.0.1:43123> 。`npm run build` 会先做类型检查。发布时构建带上 `/Project_3/` 前缀，见 `.github/workflows/deploy.yml`。

### 数据怎么流

`src/main.tsx` 挂上 `App`。`App` 用 `loadBundledScript()` 把 `content/chapter-01.yaml` 和 `content/chapter-02.yaml` 按顺序合成一份剧本，再跑检查。检查失败时整页只显示错误，游戏不开始。地址哈希是 `#map` 时渲染结构图 `ScriptMap`，否则渲染 `Game`。

合成规则在 `src/engine/loadScript.ts`：节拍按文件顺序接成一条列表，每拍记下所属章。标题和人物表用第一章的。后一章的 `requires` 可以指向前一章。旗标不按章清掉。

`Game` 通过 `useEngine` 持有引擎状态。状态一变就写入 `localStorage`。读档时若完成列表、激活列表或消息对不上当前节拍，整档丢掉。`sync-roots` 会把存档里还没有的根节拍补进激活列表；被已完成节拍的线性 `next` 指到的下一拍也会补上。没被选中的选项分支保持未激活。

界面不解释剧情。`ChatPane` 在一侧可以开始时派 `arm`，用计时把当前句提交进去。玩家只派 `choose`。逐字出现的间隔、打完后的停顿、各种「正在输入」时长在 `src/presentation.ts`。系统开启减少动态效果时，逐字改成直接出现。正在出来的句子可以跳过。

宽屏（768px 及以上）两栏并排。更窄时一次只看一栏，用页签切换；没在看的那一栏有新消息时，页签和一条横幅会标出来。右上角「调试」默认关。打开后能看到旗标，以及某一侧为什么还不能往下走。被挡住的原文不会出现在调试条里。头像是名字的第一个字。

### 引擎在管什么

纯函数在 `src/engine/scheduler.ts`，React 侧的动作在 `src/engine/reducer.ts`。状态是：已完成的节拍、旗标、已激活的节拍、已经出现的消息、左右两侧各自的 `pending`。

一拍的播放顺序：

1. `pending.kind = "lines"`，按 `lines` 逐句提交。
2. 有 `choices` 时变成 `choices`，等玩家点。
3. 点中后变成 `reply`，再提交那条 `reply`。提交时才写入 `set` 里的旗标，把 `next` 放进激活列表，并把这一拍标成完成。
4. 没有选项时，台词播完就按节拍上的 `next` 完成这一拍。

同一侧下一拍能不能开始，要同时满足：已经激活、还没完成、`when` 对得上、`requires` 里的节拍都已完成。同一侧有好几拍同时满足时，按文件里的先后顺序播。

`when` 的三种结果：旗标还没写过，这一拍继续等；旗标对不上，这一支隐藏，不当作挡住玩家的锁；全部相等，才算通过。

根节拍是没有任何 `next` 指向它的拍，开局就激活。其余节拍在指向它的那一下被选中或线性播完之前保持未激活。因此汇合要写成多条选择共用一个 `next`，或者让线性的 `next` 指向同一拍。

一侧的 `pending` 有三种：`lines`（正在播第几句）、`choices`（在等点）、`reply`（已点中，回复还没发完）。

### 剧本字段

正式台词只在 `content/`，一章一个 YAML。检查在 `src/engine/validate.ts`，启动时执行。过不了检查，页面不会进入游戏。

| 字段 | 含义 |
| --- | --- |
| `id` | 节拍编号，全章合并后仍唯一 |
| `channel` | `left` 或 `right` |
| `requires` | 这些节拍都完成后才允许开始。可以指向另一侧、另一章 |
| `when` | 旗标必须等于这些值。对不上的分支不出现 |
| `aside` | 选项上方的自言自语，不进聊天记录 |
| `lines` | 先播的台词。`from` 是人物 id |
| `lines[].delivery` | `type` 逐字，`pop` 一下子出现，`image` 图片（`text` 是路径，可带 `caption`），`thought` 不发出去的内心 |
| `choices[].thought` | 玩家点的想法 |
| `choices[].reply` | 随后发出的另一句 |
| `choices[].set` | 记下的旗标。值只能是文字、数字或布尔 |
| `choices[].next` | 说完后这一侧解锁的下一拍 |
| `next` | 没有选项时，台词播完去哪。不写就表示这一侧先到这里 |
| `chapter` | 章号，从 1 起。文件顶上写一次，合并时抄到每一拍 |

人物在文件开头的 `speakers`。带 `channel` 的人只能出现在自己那一侧。`ai` 不带 `channel`。现在的 id 是 `boy`、`girl`、`ai`。

检查会拦住这些情况：id 重复、引用不存在、`next` 跨到另一侧、有选项的拍又写了节拍上的 `next`、说话人不在人物表或站错侧、`requires` 成环。成环会直接停住，并写出环上的 id。

## 接着做时不要改掉的前提

- 新台词只来自已经写明的原文。缺口留在 `GAPS.md`，不要补句。
- 玩家点的想法和发出去的回复保持两句不同的话。
- 一侧内部的跳转用 `next`。等另一侧用 `requires`。按旗标分叉用 `when`。
- 几条选择后来变成同一段时，写成同一个 `next`，并给出那一拍的原文。
- 同一侧同时能播的几拍，文件里的先后顺序就是播放顺序。
- 改剧本后跑 `npm test`。和剧情衔接有关的断言在 `src/engine/story.test.ts`。
