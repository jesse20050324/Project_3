# 记忆系统实现方案（MVP 已落地版）

> 状态：教学闭环已实现并通过测试（2026-11-04）。2026-11-08 v0.4.0 实现层重构、v0.4.1 移除调试设计后，数据模型与播控体验两节已按现状更新；实现层字段契约以 [引擎实现说明.md](引擎实现说明.md) 为准。本文记录数据模型、交互流、规则和与幕5正片规则的边界，供后续迭代与审阅。

## 一、设计依据（方法论速览）

- **阅后即焚**：AI 的聊天记录不自动保留，只有玩家主动存的记忆才留得住——玩家是 AI 的记忆管理者。
- **分窗独立**：记忆池按窗（男窗/女窗）分放、互不共享。跨窗共享等于 AI 把一扇窗里的话拿到另一扇窗当论据，破坏「两边互相看不到」的核心机制。
- **效果统一为置灰硬门**：记了能选、没记置灰，一眼可见；不做软性话术差异（软效果是否保留，待干扰项设计定稿后定）。
- 教学阶段：槽位数=候选数（无取舍），产出即用完，幕5 入场清零。

## 二、两个教学闭环

| 窗 | 存 | 用（置灰门） |
|---|---|---|
| 女窗 | CH1 R1 三变体：AI 报完地址后**女生复述一遍**（「OK，小寨华旗国际A座哈，你帮我记一下，我怕忘了」），候选挂她的复述行——记忆必须是角色说出的话，不是 AI 的话 | CH3 3.4.1 地铁问路：「给出精确路线」需记忆「店的位置」；没存→置灰，只能「凭印象指一个」→ 吐槽拍 3.4.2 → 汇合 |
| 男窗 | CH3 3.2.2/3.3.1 的①里「好像是我妹的同桌还是什么」（候选「我妹的同桌」） | CH4 4.2.2 怂了拍：「让表妹帮忙牵线」需记忆「我妹的同桌」；没存→置灰，仍有「硬着头皮直接问」「先算了」两条路，全部收束到 问/不问 终局 |

## 三、数据模型（src/engine/types.ts）

```ts
// 节拍上的候选：可高亮存档的原文片段（①用户台词或④AI回复内）
type MemoryCandidate = { 缩略标签: string; 短句: string; 类型?: string; 线?: string };
// Choice 扩展：置灰门
type Choice = { thought; reply; set?; next?; 需记忆?: string };
// Beat 扩展
type Beat = { ...; 记忆候选?: MemoryCandidate[]; 清空记忆?: "all" | Channel };
// 运行时：已存记忆按窗分池
type MemoryEntry = { label: string; text: string; beatId: string };
type EngineState = { ...; memories: Record<Channel, MemoryEntry[]> };
```

- **保存**：`saveMemory(state, channel, entry)`——同缩略标签去重，只入本窗池（`scheduler.ts`）。
- **判定**：`hasMemory(state, channel, label)`——置灰门用。
- **拦截**：`choose()` 里对未满足 `需记忆` 的选项报错（reducer 把错误写进 `state.error` 并在控制台输出；UI 层已置灰，正常点不到）。
- **清空**：`清空记忆` 指令在节拍完成时执行。第五章由 `tools/ch5-timing.yaml` 的 `清空教学记忆` 给六个入场变体拍分别注入 `清空记忆: left/right`，不写进定稿剧本源。
- **校验**：`validateScript` 检查所有 `需记忆` 引用的标签必须有候选提供，且短句一字不差出现在本拍台词或回复里，否则剧本拒载。
- **持久化**：v2 存档 `shuangxian.progress.v2`，`EngineState` 整体进 localStorage；缺字段由 `storage.ts` 归一化补齐；遇到 v1 旧档不静默清档，而是给出「剧本已更新，进度需重新开始」的明确提示后重置。

> **v0.4.0 变化**：`EngineState` 新增 `chapter`、`ritual`、`endings`、`error`、`runId`，并显式建模章切换；`Script` 新增 `axes`、`endings`、`beatById`、`orderedBeats`；`Beat` 新增 `time`/`timeRank`/`order`/`sortKey`/`window`/`ending`/`节拍`；`Line` 与 `Choice` 新增解析后的 `timing`。这些都不改变记忆池的分窗语义。

## 四、交互（按双线 UI 模板）

- **高亮**：`MessageBubble` 渲染时，消息所属节拍的候选短句若出现在文本中 → 荧光笔高亮 span；点击 → dispatch `save-memory`；已存的高亮淡化不可点。正在打字的气泡不高亮，落定后出现。用户消息左灰泡、AI 消息右纯文字，高亮只出现在有候选的文本里。
- **记忆入口**：每窗栏头一个极简图标入口（内联 SVG，不用 emoji），点击打开浮层列出本窗记忆。两个入口分窗，界面本身就是对话隔离的表达。
- **置灰选项**：`ChoicePanel` 对 `需记忆` 未满足的选项渲染灰胶囊＋「记忆可用」小标签沿用已有视觉语言，**不写长句说明**。UI 三态为 `active` / `locked` / `empty`。

## 五、剧本接口

- script 层字段（ch3/ch4/ch5 统一格式）：`记忆候选: {缩略标签, 短句, 类型, 线}`、选项 `需记忆: 标签`。v5.1 定稿**没有** `清空记忆` 字段，清零是实现层的世界观约定，由 overlay 注入。
- 引擎层（`content/chapter-0N.yaml`）：Beat 级 `记忆候选`、Choice 级 `需记忆`，`loadScript` 显式解析；未声明字段直接报错。
- 候选来源：**一律来自角色台词（①）**——AI 自己说过的话不作为候选（店址经女生复述转成她的话）；已由 `validate` 机器校验。

## 六、与幕5 正片规则的边界（不在本 MVP 内）

1. **稀缺槽位**：幕5 起每窗槽位拟设 4~5（正牌 3+干扰 2），超槽需取舍；教学阶段不限。
2. **正牌/干扰体系**：钥匙／糖／自白三类正牌＋生活趣闻干扰项，判定挂 8·二：认识到=持有本窗钥匙，缺则灰显提示；外归因永远可选。
3. **清零**：已落地——幕5 入场拍由 overlay 注入 `清空记忆`（分窗），教学记忆随幕5 开演清空。
4. **软效果**「AI 回复按记忆池持有情况出变体」：幕6 垃圾自销与 8·二 判定共用，**仍未实现**。
5. UI 升级项（飞行动画、神经网络布局、圆球）按模板约束全部不做。

## 七、测试覆盖

- `story.test.ts`：候选与门的配置正确性、第五章 8 条四格全名记忆候选、严格字段校验；
- `scheduler.test.ts`：问路门未存→精确路线报错、凭印象可走通汇合；表妹门未存→报错，其余路径正确 set 旗标；存后解锁；重复保存去重；

## 八、播控体验（全局排序驱动）

- **串行节拍**：`canArm` 仍保证两窗不并发出消息（对面正在播出时本窗不放行），这是参考稿「一活一锁」输入卡状态的基础。
- **下一拍由全局裁决**：`playbackStep()` 只挑排序键最小的可播拍。`commitLine` / `commitReply` 播完只 `completeBeat()`，**不再自动接本窗下一拍**——旧实现正是这条旁路让一条线一路播到底、女线 16 拍全部播不到，还把区间门提前关掉。排序键来自 `timeline.ts` 的 `chapter×10^6 + order`，第五章的 `order` 由 `tools/ch5-timing.yaml` 的 `拍序` 生成；运行时与穷举仿真共用，不存在两套顺序。
- **章间「上下文重置中」仪式（已根治刷新 bug）**：`chapter`、`ritual`、`endings`、`error`、`runId` 全在 `EngineState` 里并持久化。跨章由 reducer 一步完成「切章 → 清该窗消息 → 记录仪式起点」，`ritualTick()` 幂等推进 mask→pause→clear。UI 只读持久化状态显示蒙版，不靠 React 局部 `resetting` 或 `setTimeout` 计时器，也不再从 `state.messages` 最后一条反推章号。刷新、StrictMode 双调用都能恢复或幂等。已存记忆保留，清空后没存的高亮候选永久消失，这是阅后即焚的戏内落实。
- **逐消息节拍**：每条消息带解析后的 `Timing`，`ChatPane` 按 `pause → indicator → typing/shown → afterMs → commit` 驱动；全局预设／拍默认／逐句覆盖三层，详见 [引擎实现说明.md](引擎实现说明.md)。**v0.4.1 起界面不再提供速度倍率控件**，调参全部在配置文件里完成；`state.error` 由 `useEngine.ts` 在控制台输出，画面上不展示调试信息。
