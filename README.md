# He said, she said

玩家扮演一个 AI 聊天助手，同时看着左右两条互相隔离的对话。玩家不能自由打字，只能点一个带 AI 味的想法；点下去之后，聊天里出现的是另一句事先写好的回复。

**第一、三、四、五、六、七、八幕可玩**：CH1 出发前、CH3 桌游店、CH4 熟悉期铺垫、CH5 熟悉期正片（按已审定的 v5.1 定稿：40 拍、16 档游戏世界时间、6 处真分叉与汇合、6 个入场变体、严格等待门与区间门、「在一起」双窗终局）。幕号 2 空缺（旧第二章已并入第三章）。第六幕为确认关系后的官宣与纪念日邀约，第七幕为第一次摩擦及缓和，第八幕在一个月纪念日进入双窗记忆判定。

## 打开游戏

线上：<https://jesse20050324.github.io/Project_3/>。推送到 `main` 之后 GitHub Actions 会重新发布，一般一两分钟生效；浏览器缓存旧页面时强制刷新一次。游戏头部显示「v版本号 · git 短哈希」，用它核对线上是否已更新。

| 层 | 路径 | 能不能改 |
|---|---|---|
| **定稿真相** | `script/ch3.yaml`、`ch4.yaml`、`ch5.yaml`、`script/feishu/*.mmd`（飞书审稿图）、`script/design/*` | **一律只读**。给用户看的定稿绝对不能动 |
| **实现层补充** | `tools/ch5-timing.yaml`（拍序、区间门、逐消息节拍、入场旗标、教学记忆收口、终局声明） | 可改，调参只动这里 |

第五章的正文由单向生成器逐字搬运：


## 实现层 YAML 字段

顶层：`title`、`chapter`、`时间轴`（16 档游戏世界时间，值与每拍 `time` 一字不差）、`默认节拍`、`speakers`、`endings`、`beats`。

每一拍（`beats[]`）：

| 字段 | 含义 |
|---|---|
| `id` | 全章唯一。第五章两窗同号拍用 `5m.` / `5f.` 前缀区分 |
| `channel` | `left`（男生）或 `right`（女生） |
| `label` / `time` / `timeRank` | 拍标题、时间档、时间轴下标 |
| `order` | 章内显式序号；`timeline.ts` 用它算全局排序键 `chapter×10^6 + order`，旧章缺省按文件顺序 |
| `when` | 入场旗标条件，例如 `{ 男生意向: 问, 女生意向: 问 }`；三种入场变体靠它互斥 |
| `requires` | **严格等待门**：列出的拍全部完成后，本拍才允许开始。可以指向对侧 |
| `window` | **区间门**：`{ channel, 下界: [...], 上界: [...], 说明 }`。下界中至少一拍已完成才开门；上界中任一拍已完成即关门，本拍仍未播就是「顺序反了」，启动校验与仿真会报错 |
| `清空记忆` | `left` / `right` / `all`，拍完成时清对应窗的教学记忆 |
| `记忆候选` | `{ 缩略标签, 短句, 类型, 线 }`，短句必须一字不差出现在本拍台词或回复里 |
| `节拍` | 拍级默认：预设名或数值对象 |
| `ending` | 本拍参与哪个终局；`endings[]` 声明双窗共同抵达才算成立 |
| `lines` | 先播的台词。`from` 是人物 id；`delivery` 为 `type`（逐字）／`pop`（一下出现）／`image`／`thought`（AI 自语，不进聊天流）。单行可写 `节拍` 覆盖 |
| `choices` | 玩家的 `thought` 与发出去的 `reply`；可带 `set`（旗标）、`需记忆`（置灰门）、`next`（选完解锁的下一拍）、`节拍` |
| `next` | 没有选项时，台词播完去哪一拍 |

这是一张有向图，不是树：两条选择可以汇合到同一个 `next`；`activated` / `completed` 模型支持多入口、多分支与汇合。启动时会校验 id 重复、引用是否存在、`next` 跨侧、`requires` 成环、时间轴一致性、区间端点合法性、终局声明、节拍数值范围。**未声明的字段会直接报错并列出文件名、拍 id 与字段名**，不会被静默丢弃。

## 三类跨窗时序

1. **严格等待**（`requires`）：某拍播完才放行，先后固定。
2. **区间包含**（`window`）：对侧进度落在下界与上界之间即可，区间内谁先谁后无所谓；越过上界仍没播就是逻辑错误。例如「男第 3~10 拍之间女第 6 拍成立」。
3. **同段自由**：无门的同档拍按全局排序键先后播，不看消息历史最后一条在哪一侧。

排序与门判定统一在 `src/engine/timeline.ts`，运行时 `playbackStep()` 与穷举仿真共用同一份结果。`src/engine/simulate.ts` 穷举所有入场组合与选项组合，机器验证每拍可达、无死锁、无区间越界、终局可抵达。

## 逐消息节拍

每条消息解析成一个定值 `Timing`：`pauseBeforeMs`（开口前的停顿）、`indicatorMs`（三点打字态）、`typeIntervalMs`（逐字间隔）、`afterMs`（播完留白）。三层覆盖，从宽到窄：

1. **全局预设**：`src/presentation.ts` 的 `PACING`——`极快`／`快`／`正常`／`慢`／`长停顿`。想整体调快慢改这一处。
2. **章默认 / 拍默认**：YAML 顶层 `默认节拍` 与 `beat.节拍`。
3. **逐句覆盖**：`line.节拍` / `choice.节拍`，可写预设名，也可写 `{ pauseBeforeMs: 1500 }` 只覆盖单字段。第五章写在 `tools/ch5-timing.yaml` 的 `节拍.拍` / `节拍.句` / `节拍.选项` 三张表里。

UI 直接读已定值的 `timing`，不重复计算；**全部调参都在配置文件里完成，界面不提供调速控件**；系统开启「减少动态效果」时全部归零。

## 怎样交下一段正文

那是**剧本轮**的事，不属于实现层：先过 `script/设计流程.md` 五个 Phase → 写 `script/chN.yaml` → `node script/feishu/build.mjs` 出飞书图 → 用户审稿认可 → 才按上面的生成器流程迁到 `content/`。实现层不会替剧本补台词，也不会改写定稿里的任何一个字。
