# 双线

玩家扮演一个 AI 聊天助手，同时看着左右两条对话。两边各是一个人。玩家不能自由打字，只能点一个带 AI 味的想法；点下去之后，聊天里出现的是另一句事先写好的回复。

当前可玩的是「第一幕 · 出发前」：男生三轮，加上他选定店名之后女生的第一轮。女生这边没有新的选项，位置和反应跟着所选的店走。还没写的下一句在 `content/GAPS.md`。

## 运行

```bash
npm install
npm test
npm run dev
```

开发服务器地址是 <http://127.0.0.1:43123> 。

进度存在浏览器的 localStorage 里（已完成的节拍、旗标、已经出现过的消息）。要重来，点右上角「重新开始」。

「调试」默认关掉。打开之后能看到旗标，以及某一侧为什么还不能往下走。被挡住的原文不会出现在调试条里。

## 剧本文件

正式台词在 `content/`，一章一个 YAML。现在是 `content/chapter-01.yaml`。

这是一张有向图，不是一棵树。两条选择可以汇合到同一个 `next`。一侧要等另一侧，用 `requires`，不要靠把两段对白穿插着写。

每一拍：

| 字段 | 含义 |
| --- | --- |
| `id` | 节拍编号，全章唯一 |
| `channel` | `left` 或 `right` |
| `requires` | 可选。这些节拍都完成后，这一拍才允许开始 |
| `aside` | 可选。玩家看得到、但不会发进聊天的 AI 自言自语 |
| `lines` | 先播的台词。`from` 是人物 id，`delivery` 是 `type`（逐字）、`pop`（一下子出现）或 `image`（`text` 是图片路径） |
| `choices` | 可选。玩家点的 `thought`，以及随后发出的另一句 `reply` |
| `choices[].set` | 可选。记下旗标，例如 `shop: 时光桌游吧` |
| `choices[].next` | 选完并说完之后，这一侧解锁的下一拍 |
| `next` | 没有选项时，台词播完去哪一拍。不写就表示这一侧先到这里 |

同一侧如果有好几拍同时满足条件，按文件里的先后顺序播。`next` 必须指向同一侧已经存在的节拍。`requires` 可以指向另一侧。启动时会检查：id 是否重复、引用是否存在、`next` 有没有跨侧、`requires` 有没有成环。成环会直接停住，并在页面和控制台写出环上的 id。

人物在文件开头的 `speakers`。现在左侧是「男生」，右侧是「女生」，玩家发出的气泡署名是「AI」。

## 怎样交下一段正文

按拍写，不要只写「然后就不一样了」。每一拍请给全这些：

1. 在左边还是右边。
2. 谁先说了什么，用原句。
3. 玩家点的想法原句，以及点完后 AI 真正发出去的那句原句。这两句不要写成同一句。
4. 这一选要记下什么（比如选了哪家店），以及下一拍的编号。
5. 如果几条选择后来汇合，就写明它们进入同一个下一拍，并给出那一拍的原文。
6. 如果这一侧要等另一侧的某一拍结束才能开口，写明「必须等哪一拍完成」，以及等完之后的原句。

没写出来的台词不会被补上。括号里的举例、待定、以及「切到另一边」但没有另一边的句子，都不会进游戏。
