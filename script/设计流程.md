# 剧本设计流程（写任何一章前的操作规程）

> 2026-11-08 立。来源：CH5 v4 审稿暴露的三类系统性问题（时序未先行／分支外显后果未追踪／情绪钩子无反馈拍）。
> 本文件是方法论层；格式铁律见 AGENTS.md 与 ch3.yaml 文件头；宏观定稿见 outline.md。
> **写 ch6/7/8 前必须逐 Phase 过一遍，不许直接开写轮次。**

## 为什么需要这个流程

剧本是双窗共享同一个游戏世界：男窗一句 AI 建议，会改变男生实际发给女生的内容，
变成女窗里的事实。时间、先后、原话、分支后果，任何一处没对齐，玩家在两个窗口
并排一读就穿帮。这些矛盾无法靠"写完再顺读"兜住——必须在落笔前就设计死。

## Phase 0 时间轴先行（一切之前）

1. 把本章要发生的**游戏世界事件**（不是轮次）列成双窗同轴的表，粒度=天＋半天/时段。
   用 D-日编号（D1=本章第一天），标注星期（周末/工作日影响上班、加班、见面）。
2. 每个事件落位时，同时回答：男窗哪一拍展示、女窗哪一拍引用（或不出现）。
3. 明确三类跨窗约束，并在时间轴上标出来：
   - **严格先后**（等待门）：B 必须等 A 拍发生后才可出现（写成 yaml `等待`）；
   - **范围包含**：某拍落在对侧某两拍之间的区间即可，不钉死；
   - **同段自由**：同一时间块内先后皆可，无约束。
4. 落盘格式：yaml 顶层 `时间轴:` 列表（分块顺序即时间顺序）＋每拍 `时间:` 字段
   （值必须与轴条目一字不差）。build.mjs 自动生成 `chN-timeline.mmd` 时间轴图：
   纵向=游戏世界时间、越上越早，两窗并排，虚线=等待门。审稿先审时间轴图再审细图。

## Phase 1 共享事件对位

凡两窗都能感知的事件（谁先加好友、谁先发消息、约会、改期、表白、官宣……）：

1. 指定**展示窗**（事件在哪窗被完整叙述）与**引用窗**（另一侧转述/收到）。
2. 登记三件事：**谁发起、原话全文、发生时间（D+时段）**。
3. 两窗引用的原话必须**一字不差**；引用窗不得早于展示窗（挂等待门）。
4. 同一事件的两侧叙述允许"各自版本"（如她转述他的交底），但事实层（谁做了什么、
   大致原话）不得矛盾。

## Phase 2 分支传播分析

对每个分叉和每个入场变体：

1. 列出**外显行为差异**：这个选择会改变角色发给对方的内容/时机吗？
   - 改变 → 对侧窗和下游共享事件必须适配所有变体（对侧出对应变体，或用收敛拍）。
   - 不变（只改本窗内心戏）→ 下游本窗拍可分支差异化，汇合拍①须对全部前情成立。
2. **收敛拍**：变体后加一拍，让角色主动把局面收敛成一种（例：三变体各自拿到不同
   开场建议→收敛拍里他"没照建议，自己改了这句"→之后所有下游只有一种事实）。
3. 汇合拍自检：把每条能到达它的路径各读一遍①，任何一条读不通=穿帮，改通用措辞
   或补收敛。
4. AI 的建议文本会变成角色的外显行为——**建议本身也是分支的一部分**，写④时就
   要想清楚"他照做之后会发生什么"，并保证后续分支拍与④的行为一致
   （例：④让他"这就睡"，分支拍就不能写"聊到十一点多"）。

## Phase 3 节拍落位（密度与情绪连续性）

1. 按时间轴铺拍，每个焦虑/期待钩子必须在**下一拍或下下拍**有反馈拍兑现
   （AI 建议完不能就没下文；玩家要看到"第二天怎么样了"）。
2. 相邻拍时间跨度大时（如隔一周），后一拍的①开头要有连接句
   （"这一周陆陆续续聊着……"），不许裸跳。
3. 每窗每章 ≥2 处真分叉（铁律6）；分支拍数≥1，1-2 拍内收回。
4. 检查两侧节拍的**对位关系**是否与 Phase 0 的时间轴一致
   （例：女窗"已聊几天的具体分享"应落在男窗"刚开始热聊"之后的区间）。

## Phase 4 写轮次

按 AGENTS.md 七条铁律＋ch3.yaml 文件头格式规范写。每拍必含 `时间` 字段；
跨窗拍按 Phase 1/2 的结论挂 `等待`；共享原话从对位表粘贴，不许手打。

## Phase 5 自查三轮（交付前，一轮都不能省）

1. **合规轮**：七条铁律逐条过；候选短句一字不差出现在①且是角色的话；真分叉
   两选项不直连同一节点、1-2 拍收回；时间字段与轴完全匹配。
2. **顺读轮**：双窗按串行节拍连读，查穿帮、突兀、口吻、YAML 值不以英文引号开头。
3. **时序轮**（新）：
   - 把两窗所有拍按时间轴重排连读一遍，逐个等待门查方向（指向的必须是共享拍
     ——所有路径都经过的拍）；
   - 共享事件原话逐字比对（两窗各搜一次）；
   - 每个汇合拍按全部可达路径各读一遍①；
   - 每个情绪钩子找到它的反馈拍；每个④建议找到"他照做后"的兑现或改写；
   - 世界事实唯一性：谁先开口、输赢、时间等细节全章一致（grep 关键词核对）。

## 交付

改 `script/chN.yaml` → `node script/feishu/build.mjs`（自动出细图＋时间轴图）→
用户飞书审 → 认可后才迁 content/引擎（`npx vitest run`＋`npx tsc --noEmit` 全绿）→
bump version 并 push。定稿内容才同步 outline.md。
